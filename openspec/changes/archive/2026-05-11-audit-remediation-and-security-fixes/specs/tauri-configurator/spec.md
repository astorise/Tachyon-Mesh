# Specification: Tauri Security, Validation, and Flow Orchestration

## 1. Stronghold Security Remediation
The current implementation of `write_secure_profile` writes JSON in plaintext to `tachyon-stronghold-auth-profile.json`. This must be replaced with the actual Tauri Stronghold state API.

* **API Usage:** In `tachyon-ui/src/main.rs`, obtain the Stronghold state via `app.handle().state::<Stronghold>()`. Use `.insert_record("auth_profile", bytes)` and `.get_record("auth_profile")`.
* **Plaintext Removal:** Delete any code utilizing `tokio::fs::write` for passwords or tokens.
* **Remember Credentials UI:** Ensure the toggle defaults to `false`. If a user attempts to check it and Stronghold initialization failed, display a red warning toast and prevent the action.

## 2. Stateless Step-Up MFA
The current Step-Up MFA flow relies on the plaintext password stored in the profile to perform a background login.
* **Client Side:** Update the MFA prompt logic to expect a short-lived `mfa_session_token` upon successful TOTP validation, instead of re-sending the password.
* **Host Side:** The core host must emit this token (or update a secure HTTP-only cookie) that elevates the session privileges for a configurable grace period (e.g., 20 minutes) without requiring the original password.

## 3. WIT-Based Validation
Currently, `wit_bindgen!` is called but the generated code is unused.
* **Wire Bindings:** In `validate_traffic_config` (and equivalent functions for other domains), map the incoming `serde_json::Value` to the structs generated by the `traffic-management-config` world (and others).
* **Missing Contracts:** Add `wit_bindgen!` invocations for the other 4 configurations (`config-ai.wit`, `config-observability.wit`, etc.) and enforce their use in the validation handlers.

## 4. Atomic Apply & Seal Flow
Currently, users must manually apply and then seal configurations.
* **Network Utils:** Create `applyAndSeal(domain: string, payload: any)` in `network.ts`.
* **Orchestration:** This function must:
    1. Send a dry-run/diff request to the host.
    2. Prompt the user with a visual diff confirmation modal.
    3. Trigger Step-Up MFA if the endpoint requires it.
    4. Execute the seal followed immediately by the apply.
* **Panel Updates:** Update `TachyonConfigDashboard` subclasses to invoke this new atomic flow instead of discrete steps.
