## 2. Runtime wiring

- [x] 2.1 In `try_load_with_topology` (`candle_llm_runtime.rs`), replace the unconditional `flashinfer_attention` rejection with an architecture/device/feature gate: `flashinfer_attention_supported = single_device_cuda_supported && cfg!(feature = "candle-flashinfer") && requested_device != "cpu"` — the extra `candle-flashinfer` check (beyond paged_attention's pattern) is required because, unlike `flash-attn`, `candle-transformers/flashinfer-kernels` is not unconditionally bundled into the `candle-cuda` feature; without it a `candle-cuda`-only build would report this as supported and panic at decode time (`unimplemented!(...)`). Every other combination keeps the existing typed rejection. **Bug caught by an automated (Codex) review and fixed**: `single_device_cuda_supported` didn't check `distribution_mode == Single`, so a tensor/pipeline/expert-parallel Llama request on CUDA would pass this gate and then silently dispatch to `load_parallel`, whose `Config` never sets `use_flashinfer_attention` — accepted but not actually wired. Fixed by requiring `distribution_mode == Single` in `single_device_cuda_supported` itself (shared by `paged_attention_supported` too, which had the identical pre-existing gap from `wire-paged-attention-decode-path`). Regression tests added: `flashinfer_attention_strategy_is_rejected_for_a_non_single_distribution_mode` and `paged_attention_strategy_is_rejected_for_a_non_single_distribution_mode` (both CPU-testable, no `candle-cuda` needed — `distribution_mode != Single` alone triggers rejection).
- [x] 2.2 Reject the combination of `flashinfer_attention: true` and `paged_attention: true` with a typed error rather than silently picking one.
- [x] 2.3 Thread the new `use_flashinfer_attention` config flag through `load_safetensors`'s Llama arm (set from `strategy.flashinfer_attention`) — no dtype change needed, unlike `paged_attention`'s BF16 switch. The field exists on `Config` regardless of the `candle-flashinfer` feature (only its dead-code lint is feature-gated fork-side), so the assignment is unconditional and safe.
- [x] 2.4 Confirmed LoRA adapters and speculative decoding compose without special-casing: `generate_with_adapter_streaming` rebuilds its model from the same `config` `load_safetensors` set `use_flashinfer_attention` on, so LoRA inherits it automatically (LoRA only touches the projection weights, not which attention kernel runs afterward — orthogonal concerns). Speculative decoding's fallback (`is_paged_attention_enabled()`) is unaffected since `use_flashinfer_attention` is a load-time `Config` flag, not external per-request state like `paged_attention`'s `PagedAttentionRuntime`/dtype switch — no dtype-mismatch risk, so no fallback was added for flashinfer specifically.
